# H12. Ring 3 y llamadas al sistema

**Fase:** 3

## Objetivo

TSS, segmentos de usuario, ring 3, int 0x80, validación de punteros.

## Criterio de aceptación

Un programa en ring 3 escribe `Ola do ring 3!` y termina; `cli` en ring 3 termina solo ese proceso.

## Resultado

**Concluida.** Código en `kernel/nucleo/sistema.c`, `kernel/nucleo/chamadas_processos.c`, `kernel/arch/excecoes.c`, `kernel/arch/gdt.c` (TSS), `kernel/inc/abi.h`; decisión D012.

- TSS con la pila del kernel de cada proceso; segmentos de usuario en la GDT; marco inicial para el anillo 3 (IOPL=0).
- `int 0x80` (puerta accesible desde el anillo 3) con la tabla de llamadas del PRD 4.5 (abi.h), con un despacho que gestiona el bloqueo con repetición (D010).
- `usuario_ok`/`usuario_texto`: validación de todo puntero que venga del anillo 3.
- Una excepción en el anillo 3 termina solo el proceso, con el mensaje `[SaguiOS] Processo N (nome) encerrado: motivo`.
- Implementadas en esta historia: `sair`, `pid`, `matar`, `esperar`, `dormir`, `tempo`, `data`, `info_sistema`, `aumentar_memoria`, `reiniciar` y `escrever` para la pantalla (el resto del grupo de archivos, en la H14).
- Prueba `tests/h12_anel3.py` (autoprueba `anel3`): un programa en el anillo 3 escribe `Ola do ring 3!` y termina con código 42 (el kernel rechazó un puntero a su propia memoria); `cli` en el anillo 3 termina solo ese proceso; leer la memoria del kernel genera un fallo de página y termina el proceso; toda la memoria se recupera.
