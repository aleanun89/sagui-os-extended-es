# H10. Paginación

**Fase:** 3

## Objetivo

Directorio y tablas de páginas, kernel en todos los espacios, fallo de página con mensaje claro.

## Criterio de aceptación

Dos espacios de direcciones con valores distintos en la misma dirección virtual; un acceso no válido genera la pantalla de fallo de página.

## Resultado

**Concluida.** Código en `kernel/mem/paginacao.c`; decisión D010.

- Paginación de 2 niveles con páginas de 4 KB; kernel mapeado 1:1 hasta 896 MB (página 0 sin mapear, para cazar punteros nulos), franja de ventanas 0x38000000-0x3FFFFFFF para dispositivos, área de los programas de 0x40000000 a 0xBFFFFFFF.
- Las tablas del kernel se crean en el arranque y las comparten todos los directorios.
- `espaco_criar`, `espaco_destruir` (devuelve páginas y tablas), `espaco_mapear`, `espaco_traduzir`, `espaco_alocar`, `janela_mapear`.
- CR0: PG (paginación), WP (el kernel respeta las páginas de solo lectura) y EM (una instrucción de FPU genera una excepción, porque el estado de la FPU no se guarda).
- La pantalla de fallo de página explica la operación (lectura/escritura), la dirección, si la página estaba ausente o protegida y el modo (kernel/usuario).
- Prueba `tests/h10_paginacao.py`: autoprueba `paginacao` (la misma dirección virtual lee 0x11111111 en un espacio y 0x22222222 en el otro, páginas físicas distintas, kernel visible en ambos, todo devuelto al destruir) y autoprueba `falta_pagina` (leer 0x90000000 genera la pantalla).
